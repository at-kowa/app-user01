# 物件状況ボード（架空データの試作）

物件ごとの受注・材料・工程・不良を、営業・業務・現場・工場長の4つの役割が同じ1画面で見るための試作です。生成AI研修の課題として作っています。

- **データはすべて架空です。** 実在の会社名・客先名・品番・図面・単価・金額・個人名は入れないでください
- このリポジトリは公開されています。鍵・パスワード・ログイン用のメールアドレスは置きません
- 保守は作成した部署が行う前提です
- 要件は [docs/requirements.md](docs/requirements.md)（第2版）

## いまの段階

| 段階 | 内容 | 状態 |
|---|---|---|
| 1 GitHub | Next.js ＋ shadcn/ui で画面を作る | 済み |
| 2 Supabase | データベースとログイン（役割別アカウント）につなぐ。書ける欄の制限はデータベースでも止める | 作成中 |
| 3 Vercel | URLで使えるように公開する（無償版・試作のみ） | これから |

## できること

- 一覧：状態を5色で表示（遅れ＝赤／材料待ち＝黄／進行中＝青／引合＝白／出荷済み＝グレー）、納期注意（残り7日以内）・不良ありの目印、件数での絞り込み、担当班での絞り込み、納期の近い順
- 詳細：受注・材料・工程・不良・変更履歴。書ける欄は役割で決まる
- ログインしていない人、役割を登録していないアカウントには何も見せない

| 役割 | 受注欄 | 材料欄 | 工程・不良欄 | 物件の追加・削除 |
|---|---|---|---|---|
| 営業 | 書く（受注区分・出荷予定日を除く） | 見る | 見る | できる（引合で登録） |
| 業務 | 書く | 書く | 見る | できる（受注で登録） |
| 現場 | 見る | 見る | 書く | — |
| 工場長 | 見る | 見る | 見る | — |

## データの場所と鍵

| もの | 場所 |
|---|---|
| 物件・材料・工程・不良・変更履歴・役割 | Supabase（研修用の共有プロジェクト）の `app_user01_` で始まる表 |
| 表・権限・初期データを作るSQL | [supabase/](supabase/)（01_schema → 02_seed → 03_roles の順に、人が SQL Editor で実行する） |
| 接続先と公開用キー | PCは `.env.local`、公開版は Vercel の環境変数（どちらも人が入れる。値はここに書かない） |

`.env.local` は [.env.example](.env.example) をコピーして作ります。秘密キー（secret／service_role）は使いません。

## PCで動かす

Node.js 22 以上が必要です。

```
npm install
npm run dev
```

Microsoft Edge で http://localhost:3000 を開き、役割のアカウントでログインします。

社内のネットワークで `npm install` が証明書のエラーで止まるときは、PowerShell で `$env:NODE_OPTIONS='--use-system-ca'` を設定してから実行してください。

## データベースの権限を確かめる

```
npm run check:db            # ログインして書き込みも試す（人が実行する）
npm run check:db -- --anon  # ログインせずに読むだけ
```

`.env.local` に確認用アカウント（CHECK_…）を入れておきます。確認用に作った物件は最後に消えます。

## 困ったとき

| 症状 | 対処 |
|---|---|
| ログインできない | アカウントとパスワードを作成者に確認する |
| ログインしても「役割が登録されていません」と出る | 役割の表に登録されていない。作成者に `supabase/03_roles.sql` での登録を頼む |
| 「データを読めませんでした」と出る | 研修用のデータベースが一時停止している（7日使わないと止まる）。管理者に再開を頼む |
| 「保存できませんでした」と出る | その欄を書ける役割かを確かめる（理由は画面に出る） |
| 初期データに戻したい | `supabase/02_seed.sql` を人が SQL Editor で実行する（全員のデータが初期に戻る） |
| 「接続先が設定されていません」と出る | `.env.local`（公開版は Vercel の環境変数）に URL と公開用キーが入っていない |

## 変更のしかた

作業ブランチで変更 → プルリクエスト → 人が中身を見てマージ。main への直接の push はしません。データベースの変更は supabase/ にSQLを足し、人が中身を見て実行します。
